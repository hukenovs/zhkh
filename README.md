# zhkh

Авто-сбор квитанций ЖКХ из личных кабинетов: логинимся, забираем PDF за последний месяц, парсим сумму к оплате, складываем локально.

## Зачем это нужно

Платёжки за московскую квартиру разъехались по 4+ независимым кабинетам: МОЭК (отопление и ГВС), Мосводоканал (ХВС и канализация), Мосэнергосбыт (электричество), УК (содержание, домофон, антенна и пр.). У каждого свой логин, своя вёрстка, свои промо-модалки и капчи, свой формат PDF и своё место, где спрятана «сумма к оплате». Раз в месяц приходится:

1. Залогиниться в каждый кабинет по отдельности.
2. Прокликать до текущего месяца (везде по-разному).
3. Скачать PDF.
4. Где-то отдельно увидеть сумму, где-то выковырять из самой квитанции.
5. Сложить всё в одну табличку и оплатить.

`zhkh` делает всё это сам: один прогон — все квитанции в `receipts/YYYY-MM/<site>/`, сводная таблица сумм в терминале, итог по месяцу. Никаких ручных кликов, никаких потерянных квитанций, ничего не зависит от рассылок на почту (которые приходят с лагом и не для всех сайтов).

Логика парсеров под капотом — Playwright поверх Chromium: тот же кабинет, что и у человека, просто без человека. Креды лежат локально в `~/.zhkh.keys`, никуда не уходят.

## Что поддерживается

| Сайт | Что делает | Сумма | Объекты |
| --- | --- | --- | --- |
| `moek` — elk.moek.ru | Логин → `/fl/payments` → клик «Скачать» в карточке ЛС | «К оплате» из карточки | по числу ЛС |
| `mosvodokanal` — onewind.mosvodokanal.ru | Выбор ФЛ → логин → вкладка «КВИТАНЦИИ» → клик по верхней строке грида → «Печать квитанции/счета» | Сумма последней квитанции из таблицы | 1 ЛС |
| `mosenergosbyt` — my.mosenergosbyt.ru | Логин → закрытие промо-модалок → обход всех ЛС из сайдбара → «История» → «Квитанции» → «Печать квитанции» в шапке последнего месяца | Сумма к оплате из шапки месяца | все ЛС из сайдбара |
| `etalonuk` — cab.etalonuk.ru | Логин (телефон с маской + 2 галочки) → закрыть онбординг «Перейти в платежи» → «Квитанции и начисления» → обход всех объектов из верхнего селектора → клик «Квитанция» | «Итого» (если 0, берётся «Долг») | все объекты из селектора |


## Установка

Требования: macOS / Linux, Python 3.11+, [uv](https://docs.astral.sh/uv/).

```bash
# 1. uv (если ещё не стоит)
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"

# 2. зависимости проекта (создаст .venv/ автоматически)
uv sync

# 3. браузер для Playwright (~150 МБ)
uv run playwright install chromium
```

## Креды

Заводим `~/.zhkh.keys` (YAML), кладём логины и пароли по сайтам. Шаблон — `.zhkh.keys.example`.

```yaml
moek:
  login: "user@example.com"
  password: "..."

mosvodokanal:
  login: "user@example.com"
  password: "..."

mosenergosbyt:
  login: "user@example.com"
  password: "..."

etalonuk:
  login: "+79991234567"          # телефон РФ
  password: "..."

# опционально — VLM-разбор квитанций (см. «Суммаризация квитанций»)
openrouter:
  api_key: "..."
  model: "qwen/qwen2.5-vl-72b-instruct:free"   # бесплатная OCR-grade VLM
  pdf_engine: "pdf-text"                        # бесплатный парсер цифровых PDF

# опционально — для Telegram-бота (см. «Telegram-бот»)
telegram:
  token: "123456789:AA..."        # у @BotFather
  allowed_chat_ids:               # бот отвечает только этим chat_id
    - 11111111
```

Закрой права: `chmod 600 ~/.zhkh.keys`.

Если для какого-то сайта секции нет — он будет пропущен, ошибки не будет.

## Запуск

Все варианты эквивалентны, выбирай удобный.

```bash
# 1. через uv (без активации окружения)
uv run run.py
uv run run.py --site moek --headed --debug

# 2. активировав venv (привычный python)
source .venv/bin/activate
python run.py
deactivate

# 3. напрямую venv-питоном
.venv/bin/python run.py
```

Системный `/usr/bin/python3` (3.9 на macOS) не подойдёт — проект на 3.11+.

Флаги `run.py`:

| Флаг | Значение |
| --- | --- |
| `--site <name>` | один или несколько сайтов; можно повторять. По умолчанию — все доступные |
| `--keys <path>` | путь к файлу с кредами (по умолчанию `~/.zhkh.keys`) |
| `--headed` | показать окно браузера (полезно для отладки) |
| `--debug` | подробные логи + скриншоты и HTML на каждой стадии |
| `--summarize` | после сбора разобрать квитанции через VLM (см. «Суммаризация квитанций») |

## Что появляется на диске

```
receipts/
  2026-06/
    moek/                       <timestamp>_Квитанция за май 2026.pdf
    mosvodokanal/               <timestamp>_Платежный документ.pdf
    mosenergosbyt/              <timestamp>_<ЛС>_Счёт <ЛС> 2026-05.pdf  (по одному на ЛС)
    etalonuk/                   <timestamp>_<адрес>_5_2026.pdf

debug/                          (только при --debug)
  2026-06-11_001234/
    moek/01_landing.png, 01_landing.html, ...
    mosvodokanal/...
```

`receipts/` и `debug/` в `.gitignore`. Скачивая повторно, файлы дописываются (имя содержит таймштамп) — старые не перезаписываются.

В конце прогона печатается таблица с разбивкой по сайтам / объектам / периодам / суммам и общий итог.

## Суммаризация квитанций (VLM)

Сумма к оплате парсится прямо из кабинета — но не каждый сайт отдаёт разбивку по услугам, а где-то сумма спрятана только в самом PDF. Режим суммаризации скармливает скачанные квитанции VLM-модели через [OpenRouter] и достаёт структуру: поставщик, расчётный период, разбивка по услугам, итог, примечание (долг/пени/аванс).

Нужна секция `openrouter` в `~/.zhkh.keys` (см. выше). По умолчанию — бесплатная `qwen/qwen2.5-vl-72b-instruct:free`: в бенчмарках по извлечению данных из документов она обгоняет даже специализированный `mistral-ocr`. Список других бесплатных и платных VLM — в комментариях `.zhkh.keys.example`. PDF разбираются движком `pdf-text` (бесплатно, для цифровых PDF); для сканов можно поставить `pdf_engine: mistral-ocr` (платно).

```bash
uv run run.py --summarize                 # собрать всё и разобрать
uv run run.py --site moek --summarize     # только МОЭК
```

После обычной таблицы печатается вторая — VLM-разбор по каждой квитанции и итог.

[OpenRouter]: https://openrouter.ai/models?max_price=0

## Telegram-бот

Тот же сбор, но из чата: бот по кнопке заходит во все настроенные кабинеты, присылает текстовое саммари по суммам к оплате и сами файлы квитанций (они также сохраняются локально в `receipts/`).

Настройка:

1. Создать бота у [@BotFather](https://t.me/BotFather), получить токен.
2. Узнать свой `chat_id` (например, у [@userinfobot](https://t.me/userinfobot)).
3. Добавить секцию `telegram` в `~/.zhkh.keys` (см. выше). Бот отвечает **только** на `chat_id` из `allowed_chat_ids` — остальных молча игнорирует (бот ходит в ЛК с реальными платежами).

Запуск:

```bash
uv run run_bot.py          # или: zhkh-bot   (после uv sync)
uv run run_bot.py --debug  # подробные логи
```

В чате: `/start` — приветствие с кнопками, `/help` — справка.

- **«Запросить квитанции»** — запускает сбор (несколько минут; одновременно выполняется только один запрос), присылает саммари и файлы.
- **«Суммаризировать»** — VLM-разбор скачанных квитанций (см. «Суммаризация квитанций»). Использует последний сбор, а если его не было — сперва соберёт. Кнопка появляется только при настроенной секции `openrouter`.

## Архитектура

```
src/zhkh/
  config.py        чтение ~/.zhkh.keys, dataclass'ы
  log.py           rich-логи (Console + RichHandler)
  storage.py       пути receipts/<YYYY-MM>/<site>/ и debug/<run-stamp>/<site>/
  base.py          BaseParser, Receipt, ParseResult
  runner.py        run_parsers() — общий прогон парсеров (CLI и бот)
  summary.py       iter_summary_rows / grand_total — итог для таблицы и чата
  llm.py           OpenRouter VLM-клиент, summarize_results() — разбор квитанций
  cli.py           click-CLI, итоговая таблица, --summarize
  tgbot/
    __init__.py    реэкспорт run_bot / main_bot
    bot.py         Telegram-бот (python-telegram-bot): хендлеры, Application
    format.py      build_text_summary / build_llm_summary — HTML-текст для чата
  sites/
    __init__.py    PARSERS = { name: Cls }  — регистрация
    moek.py
    mosvodokanal.py
    mosenergosbyt.py
    etalonuk.py
run.py             точка входа CLI (uv run / python / shebang)
run_bot.py         точка входа Telegram-бота
```

Каждый парсер реализует `BaseParser.run() -> ParseResult`. ParseResult содержит список `Receipt`. У одного сайта может быть несколько Receipt-ов (например, в Мосэнергосбыте — один на каждый ЛС).

Все парсеры построены по одной схеме: Playwright + Chromium, ловля download через `page.expect_download`, скриншот и HTML-дамп на каждой ключевой стадии, чтобы было что показать при поломке вёрстки.

## Добавление нового сайта

1. Создать `src/zhkh/sites/<name>.py`, реализовать класс `…Parser(BaseParser)` с `name`, `url`, `run()`.
2. Зарегистрировать в `src/zhkh/sites/__init__.py` в словаре `PARSERS`.
3. Добавить секцию в `~/.zhkh.keys`.

Хороший шаблон — `etalonuk.py` (одиночный ЛС) или `mosenergosbyt.py` (несколько ЛС).

## Известные особенности и грабли

- **Мосэнергосбыт** блокирует не-российские IP. С активным VPN (вне РФ) `my.mosenergosbyt.ru` молча таймаутит.
- **Мосводоканал** показывает капчу при подозрительной активности — пока не реализован обходной путь через `storage_state`. При капче выводится понятная ошибка.
- Все сайты — SPA. При смене вёрстки в кабинете селекторы могут поплыть; в `--debug` есть скрины и HTML-дампы каждой стадии, по ним легко увидеть, что сломалось.
- Сети случаются — `Timeout 10000ms exceeded` на одном из шагов означает «попробуй ещё раз». Прогоны независимые.
